# Beacon PHP 1.1.0

> Superseded by 1.1.1. The 1.1.0 GitHub artifact unintentionally included CI-only files and must not be deployed. The immutable tag is retained for auditability.

Beacon PHP 1.1.0 adopts a two-repository architecture and removes the permanent downstream copy of OpenTelemetry PHP Contrib.

## Highlights

- `beacon-php-instrumentation` remains the native PHP hook extension.
- `beacon-php` is now a lightweight Agent and distribution package at the repository root.
- Framework, database, and client instrumentation is installed directly from official `open-telemetry/opentelemetry-auto-*` Composer packages.
- The new `beacon-php components` command reports 28 supported official component packages.
- The new `beacon-php install <alias>...` command installs selected components into the current Composer project.
- `beacon-php doctor` now checks the extension distribution, SDK, OTLP exporter, zero-code configuration, and installed component packages. JSON output is available with `--json` and does not expose OTLP credentials.
- Release validation now exercises official PDO auto-instrumentation against a real OTLP receiver.

There is no `beacon-php-contrib` repository and no full Contrib source mirror in the release artifact.

## Requirements

- PHP 8.2 or PHP 8.4
- Beacon PHP Instrumentation `v0.1.0` or a compatible `ext-opentelemetry >= 1.4.2` build carrying the Beacon distribution marker
- Composer 2

## Upgrade

Install the Beacon extension first, then update the Agent package and select only the components used by the application:

```bash
composer require beacon-observability/beacon-php:1.1.0
vendor/bin/beacon-php install pdo guzzle
vendor/bin/beacon-php doctor
```

Applications that previously depended on component source from the Beacon monorepo must replace those path or VCS repositories with the corresponding official Composer packages.

## Rollback

Rollback the application dependency to `beacon-observability/beacon-php:1.0.0` and restore the previous component repository configuration. The separately installed native extension does not need to be downgraded when it remains at `v0.1.0`.
