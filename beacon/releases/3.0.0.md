# Beacon PHP 3.0.0

## Breaking Security log binding

Security now exports compact single-line schema-v2 JSON directly in the OTel
LogRecord Body. `observed_at` moves to native event time and `occurrence_id`
moves to the `event_id` log attribute. `source` remains in Body and attributes;
all other field paths, decoded values and nesting remain unchanged. There is no
SIEM envelope or `message` wrapper. Fingerprint v1 and the inventory ID algorithm
are unchanged. Queueing and retries retain event time and identity. Record byte
budgets and inventory partitioning use the final compact UTF-8 Body.

The Security contract is pinned to `d9d76e5a41d974d294bb596e06918bb954319bf6`. Diagnostic JSONL retains a
local wrapper with `time_unix_nano`, `attributes` and the compact `body` string;
that wrapper is not transmitted as OTLP Body. Update consumers before upgrading.

## Distribution and compatibility

The library ZIP, isolated runtime TAR.GZ, compiled installer, license and checksum
manifest are distributed as immutable GitHub assets. The native hook engine
remains the separately released Beacon PHP instrumentation 1.1.0. PHP 8.2–8.4
Linux glibc x86_64 standalone/Composer lifecycle and OTLP acceptance are validated
by the release pipeline; do not infer broader platform support from source.
There is no Packagist publication claim.

Default no-evidence filtering, opt-in Security and existing component coverage are
unchanged. Rollback to Agent 2.0.0 with the matching SIEM consumer and runtime;
use that release's immutable installer and checksum manifest. Receipt in a
Collector is not evidence of backend persistence.
